## Step 5: Add OAuth login initiation server function

Create a server function that generates PKCE + state, stores them, and redirects to Google.

**File:** `crates/tafl.online/src/main.rs`

**Add:**
- `#[get("/api/auth/login")]` server function
  - Generate PKCE verifier + challenge
  - Generate random state
  - Build Google auth URL with params: `client_id`, `redirect_uri`, `response_type=code`, `scope=openid email profile`, `code_challenge`, `code_challenge_method=S256`, `state`
  - Store `(state, code_verifier)` in a server-side in-memory store (e.g., `HashMap<String, (String, Instant)>` behind `Arc<RwLock<...>>`) keyed by state
  - Return redirect response (302) to Google URL

---

## Step 6: Add OAuth callback server function

Handle the redirect from Google, exchange code for tokens, fetch user info, upsert user, create session.

**File:** `crates/tafl.online/src/main.rs`

**Add:**
- `#[get("/api/auth/callback")]` server function with query params `code` and `state`
  - Validate `state` against the in-memory store, remove it
  - Exchange `code` for `access_token` by POSTing to `GOOGLE_TOKEN_URL` with `client_id`, `client_secret` (from env), `code`, `redirect_uri`, `grant_type=authorization_code`
  - Fetch user info from `GOOGLE_USERINFO_URL` using the access token
  - Upsert user in SQLite (insert or update by `google_id`)
  - Create a session token (random UUID or similar), store `(session_token, user_id)` in server-side store
  - Set session cookie on response and redirect to `/`

## Step 7: Add auth check and logout server functions

Provide endpoints to check current session and log out.

**File:** `crates/tafl.online/src/main.rs`

**Add:**
- `#[get("/api/auth/me")]` — Read session cookie, look up user in in-memory session store, return `Option<User>` as JSON (or `Result<User, ServerFnError>`)
- `#[get("/api/auth/logout")]` — Clear session cookie, remove from in-memory store, redirect to `/`

## Open Questions

- **Client secret storage**: Should `GOOGLE_CLIENT_SECRET` live in `.env` (dev) or be injected via env vars in production?
- **Session persistence**: In-memory `HashMap` is fine for single-server dev; for production, should sessions be stored in SQLite too?
- **Redirect URI**: The callback URL needs to match exactly what's configured in Google Cloud Console. What is the production domain?
